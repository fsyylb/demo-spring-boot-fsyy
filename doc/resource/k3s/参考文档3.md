# 在k3s上部署第一个nginx服务
```text
创建Deployment
在 kubernetes 中，deployment 用来部署应用，常见的集中配置含义如下

nginx-deployment.yml

apiVersion: apps/v1    #与k8s集群版本有关，使用 kubectl api-versions 即可查看当前集群支持的版本
kind: Deployment    #该配置的类型，我们使用的是 Deployment
metadata:            #译名为元数据，即 Deployment 的一些基本属性和信息
  name: nginx-deployment    #Deployment 的名称
  labels:        #标签，可以灵活定位一个或多个资源，其中key和value均可自定义，可以定义多组，目前不需要理解
    app: nginx    #为该Deployment设置key为app，value为nginx的标签
spec:            #这是关于该Deployment的描述，可以理解为你期待该Deployment在k8s中如何使用
  replicas: 3    #使用该Deployment创建一个应用程序实例
  selector:        #标签选择器，与上面的标签共同作用，目前不需要理解
    matchLabels: #选择包含标签app:nginx的资源
      app: nginx
  template:        #这是选择或创建的Pod的模板
    metadata:    #Pod的元数据
      labels:    #Pod的标签，上面的selector即选择包含标签app:nginx的Pod
        app: nginx
    spec:        #期望Pod实现的功能（即在pod中部署）
      containers:    #生成container，与docker中的container是同一种
      - name: nginx    #container的名称
        image: nginx:alpine    #使用镜像nginx创建container，
        ports:
          - containerPort: 80   #内部服务暴露的端口
这里面定义nginx使用的镜像和创建多少个实例，以及container命名标记

当我们按照需要配置好deployment，使用kubectl apply 去创建部署(常见的几个 kubectl 命令可能需要记一下)

[root@master nginx]# kubectl apply -f nginx-deployment.yml 
deployment.apps/nginx-deployment created


创建Service
当我们创建部署完毕，nginx 服务仅仅只是部署，我们还需要让它暴露出自己的服务。
这就相当于给局域网里的电脑插上了网线，从此就可以对外公开自己的服务。

nginx-service.yml

apiVersion: v1
kind: Service  #该配置的类型，我们使用的是 Service 服务类型
metadata:
  name: nginx-service  #该服务类型的名称
spec:
  selector:    #选中的app部署实例
    app: nginx #为该Deployment设置key为app，value为nginx的标签
  ports:  #暴露的端口
  - protocol: TCP  # 走得tcp 协议
    port: 80 #默认端口
    targetPort: 80 #内建服务端口
    nodePort: 30080 #对外服务端口
  type: NodePort 
这里面呢，targetPort 就是对应着 deployment 的内网端口，nodePort 则是对外公开的端口。

[root@master nginx]# kubectl apply -f nginx-service.yml 
service/nginx-service created
打开浏览器，我们可以看到nginx服务已经对外开启
```

# k3s集群需要几台服务器
```text
k3s集群的服务器数量需求根据部署场景和可用性要求有所不同，具体可分为以下三种典型配置：

1. ‌单节点部署（开发/测试环境）‌
配置说明‌：单个节点同时承担控制节点（主节点）和工作节点角色。
优点‌：资源占用极低，适合本地开发或测试环境。
缺点‌：存在单点故障风险，无高可用性保障。
示例命令‌：
bash
Copy Code
curl -sfL https://get.k3s.io | sh -

2. ‌双节点部署（基础生产环境）‌
配置说明‌：
1个主节点‌：负责集群管理、调度等控制平面功能。
1个工作节点‌：运行应用负载。
优点‌：
实现基础的角色分离，支持负载均衡。
比单节点更具容错性，某一节点故障时另一节点可暂时接管。
不足‌：控制平面仍为单点，不满足高可用要求。
3. ‌多节点高可用部署（生产级集群）‌
配置要求‌：
3个主节点‌：通过嵌入式 etcd 或其他分布式数据库（如 MySQL、PostgreSQL）实现控制平面高可用。
N个工作节点‌：按负载需求横向扩展。
负载均衡器（可选）‌：用于流量分发至多个主节点。
优点‌：
控制平面无单点故障，支持节点自动故障恢复。
支持大规模工作负载和复杂业务场景。
存储机制与节点数量的关系
嵌入式 etcd‌：需至少 3 个主节点以保证存储层的高可用性。
外部数据库（如 MySQL）‌：主节点数量可减少至 2 个（需依赖数据库自身的冗余机制）。
扩展建议
生产环境推荐采用 3 个主节点 + 负载均衡器的高可用架构，确保控制平面的稳定性。
边缘计算或资源受限场景中，可基于双节点模式优化，但需接受控制平面单点风险。
```

# k3s主节点宕机后工作节点会接替嘛
```text
‌在K3s集群中，当主节点宕机后，工作节点会自动接替其功能。‌

K3s是一个轻量级的Kubernetes发行版，专为边缘计算、物联网和资源受限环境设计。它通过简化Kubernetes的组件和减少外部依赖，使得在资源受限的环境中也能高效运行。K3s集群中的节点包括主节点（Server节点）和工作节点（Agent节点）。当主节点宕机时，工作节点会自动接替其功能，确保集群的稳定运行‌
1
2。

K3s的基本概念和架构
K3s的主要特点包括：

‌轻量级‌：K3s的二进制包大小约为50MB，启动时仅需约500MB内存，适用于资源受限的环境。
‌简化组件‌：移除非核心组件，如Alpha/Beta API和旧版存储驱动，使用SQLite替代etcd（可选外部数据库如MySQL/PostgreSQL）。
‌单一进程‌：kubelet、kube-proxy、容器运行时等合并为单一进程，降低资源消耗。
‌默认使用Flannel‌：作为CNI（容器网络接口），支持其他插件（如Calico、Cilium）。
‌自动化管理‌：包括证书分发等复杂操作，简化部署和管理‌
1
2。
工作节点接替主节点的机制
当主节点宕机时，工作节点会通过Kubernetes的自我修复机制自动接替主节点的功能。Kubernetes设计有自我修复和自我调整的能力，当检测到主节点故障时，会自动将工作负载迁移到其他健康的工作节点上，确保服务的连续性和高可用性‌
```
