# k3s超详细安装配置教程
https://blog.csdn.net/weixin_45056021/article/details/142848574
```text
在Linux上安装K3s（轻量级Kubernetes发行版）非常简单，适用于单节点或集群部署。下面是详细的步骤：

1. 系统要求
确保你的Linux服务器符合以下要求：

至少1GB内存和1个CPU核心（建议更多资源以支持更多工作负载）
支持x86_64、ARMv7或ARM64架构
Docker或其他容器运行时未被占用（K3s内置了一个轻量级的容器运行时）
2. 环境准备
首先，更新系统并确保系统包是最新的：

sudo apt-get update && sudo apt-get upgrade -y
1
安装常见的依赖包：

sudo apt-get install -y curl
1
如果你的Linux发行版是CentOS，使用以下命令：

sudo yum update -y
sudo yum install -y curl
1
2
3. 安装K3s
K3s提供了一个自动安装脚本，可以轻松在Linux系统上安装。

运行以下命令下载并安装K3s：

curl -sfL https://get.k3s.io | sh -
1
这个命令会自动下载并安装最新版本的K3s，安装完毕后，K3s会作为系统服务运行。

如果你想安装特定版本的K3s：
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION="v1.21.3+k3s1" sh -
1
4. 验证安装
安装完成后，K3s会自动启动，并且Kubeconfig文件会默认放在/etc/rancher/k3s/k3s.yaml路径下。

验证K3s是否运行成功：

sudo k3s kubectl get nodes
1
此命令会列出集群中的所有节点，并显示它们的状态。如果你能看到节点处于Ready状态，说明K3s已成功安装并运行。

5. 配置kubectl
为了更方便使用kubectl，可以将配置文件复制到用户的默认配置路径：

mkdir -p $HOME/.kube
sudo cp /etc/rancher/k3s/k3s.yaml $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
1
2
3
现在你可以通过kubectl命令来管理K3s集群了：

kubectl get nodes
1
6. 多节点集群配置（可选）
如果你想将K3s安装为多节点集群，可以按照以下步骤配置主节点（Master）和工作节点（Worker）。

6.1 安装主节点
在主节点上运行安装脚本时，加入--cluster-init参数：

curl -sfL https://get.k3s.io | sh -s - server --cluster-init
1
6.2 安装工作节点
在工作节点上，将其连接到主节点。首先，获取主节点的token：

sudo cat /var/lib/rancher/k3s/server/node-token
1
然后，在工作节点上运行以下命令，将<MASTER_IP>替换为主节点的IP地址，并使用刚才获取的token：

curl -sfL https://get.k3s.io | K3S_TOKEN=<TOKEN> sh -s - server --server https://<MASTER_IP>:6443
1
7. 管理K3s
启动K3s服务：
sudo systemctl start k3s
1
停止K3s服务：
sudo systemctl stop k3s
1
查看K3s状态：
sudo systemctl status k3s
1
8. 卸载K3s
如果你需要卸载K3s，可以运行以下命令：

sudo /usr/local/bin/k3s-uninstall.sh
1
对于工作节点，使用以下命令：

sudo /usr/local/bin/k3s-agent-uninstall.sh
1
总结
K3s的安装过程非常简便，只需要运行一个脚本即可。你可以选择单节点安装，也可以通过额外配置实现多节点集群。
```

# k3s查看所有的镜像
```text
在k3s（轻量级Kubernetes）中查看所有镜像，通常涉及到查看容器镜像的几种方式，因为k3s本质上依赖于底层的容器运行时（如containerd或CRI-O）来管理容器和镜像。下面是一些常用的方法：

1. 使用crictl工具

如果你使用的是containerd作为容器运行时，可以使用crictl工具来查看镜像。首先，确保crictl已经安装并配置正确。

查看所有镜像：

crictl images

2. 使用ctr工具

ctr是containerd的命令行工具，可以用来管理containerd的镜像和容器。

查看所有镜像：

ctr images

3. 使用nerdctl（如果使用的是nerdctl作为容器运行时管理工具）

如果你在k3s上使用的是nerdctl，可以使用以下命令：

查看所有镜像：

nerdctl images

4. 使用kubectl（针对Kubernetes资源和镜像）

虽然kubectl主要用于Kubernetes资源的管理，但你也可以通过它查看与Pods相关的镜像信息。

查看所有Pods及其镜像：

kubectl get pods --all-namespaces -o=custom-columns=NAMESPACE:.metadata.namespace,NAME:.metadata.name,IMAGE:.spec.containers[0].image

5. 使用docker命令（如果启用了Docker兼容性）

如果你的k3s集群启用了Docker兼容性（通过安装docker包或使用nerdctl），你可以使用Docker命令来查看镜像。

查看所有镜像：

docker images

总结

选择哪种方法取决于你的k3s集群配置和偏好。如果你使用的是containerd作为容器运行时，crictl或ctr是直接与之交互的好方法。如果你更习惯于Docker命令，确保你的k3s配置支持Docker兼容性。对于快速查看Pods及其使用的镜像，kubectl是一个非常有用的工具。
```

# 如何通过k3s拉取镜像
```text
以下是配置 K3s 镜像拉取的完整方案：

一、镜像仓库基础配置

修改镜像仓库配置文件‌
在 K3s 节点上创建或编辑 /etc/rancher/k3s/registries.yaml，示例如下：

yaml
Copy Code
mirrors:
  "docker.io":
    endpoint:
      - "https://registry.example.com:5000"  # 替换为国内镜像源或私有仓库地址
configs:
  "registry.example.com:5000":
    auth:
      username: <username>
      password: <password>


此文件定义镜像仓库的地址和认证信息，适用于私有仓库或加速器场景。

重启 K3s 服务‌
配置完成后执行：

bash
Copy Code
sudo systemctl restart k3s

二、镜像拉取操作

通过 Kubernetes 直接拉取‌
使用 kubectl 命令触发镜像拉取：

bash
Copy Code
kubectl run test-pod --image=my-registry.example.com/app:v1


若拉取失败，可通过 kubectl describe pod 排查错误。

通过 containerd 命令行工具‌
使用 crictl 直接操作 containerd：

bash
Copy Code
crictl pull my-registry.example.com/app:v1

三、认证私有仓库

创建 Kubernetes Secret‌
若私有镜像仓库需认证，创建 Secret：

bash
Copy Code
kubectl create secret docker-registry my-secret \
  --docker-server=my-registry.example.com \
  --docker-username=<user> \
  --docker-password=<password>


在 Deployment 中引用 Secret‌
在 Pod 或 Deployment 配置中添加 imagePullSecrets：

yaml
Copy Code
spec:
  containers:
    - name: app
      image: my-registry.example.com/app:v1
  imagePullSecrets:
    - name: my-secret


此方法确保 Pod 调度时能通过认证。

四、特殊场景处理

ARM 架构镜像拉取失败‌
确保镜像支持 ARM 架构，可通过 docker buildx 构建多平台镜像，或在 registries.yaml 中明确指定架构标签。

使用国内镜像源加速‌
安装 K3s 时指定镜像源：

bash
Copy Code
curl -sfL https://rancher-mirror.rancher.cn/k3s/k3s-install.sh | \
  INSTALL_K3S_MIRROR=cn sh -


此命令通过 Rancher 国内镜像源加速安装。

手动导入离线镜像‌
若节点无法联网，可通过 docker save 导出镜像后使用 crictl 导入：

bash
Copy Code
docker save my-image:tag > image.tar
crictl -r unix:///run/k3s/containerd/containerd.sock images import image.tar


此方法适用于完全离线环境。

五、调试技巧
查看 containerd 日志‌
bash
Copy Code
journalctl -u k3s -f | grep containerd

验证镜像配置‌
执行 crictl info 检查 registry 配置是否生效。
```

# 在k3s上部署第一个nginx服务
```text
创建Deployment
在 kubernetes 中，deployment 用来部署应用，常见的集中配置含义如下

nginx-deployment.yml

apiVersion: apps/v1    #与k8s集群版本有关，使用 kubectl api-versions 即可查看当前集群支持的版本
kind: Deployment    #该配置的类型，我们使用的是 Deployment
metadata:            #译名为元数据，即 Deployment 的一些基本属性和信息
  name: nginx-deployment    #Deployment 的名称
  labels:        #标签，可以灵活定位一个或多个资源，其中key和value均可自定义，可以定义多组，目前不需要理解
    app: nginx    #为该Deployment设置key为app，value为nginx的标签
spec:            #这是关于该Deployment的描述，可以理解为你期待该Deployment在k8s中如何使用
  replicas: 3    #使用该Deployment创建一个应用程序实例
  selector:        #标签选择器，与上面的标签共同作用，目前不需要理解
    matchLabels: #选择包含标签app:nginx的资源
      app: nginx
  template:        #这是选择或创建的Pod的模板
    metadata:    #Pod的元数据
      labels:    #Pod的标签，上面的selector即选择包含标签app:nginx的Pod
        app: nginx
    spec:        #期望Pod实现的功能（即在pod中部署）
      containers:    #生成container，与docker中的container是同一种
      - name: nginx    #container的名称
        image: nginx:alpine    #使用镜像nginx创建container，
        ports:
          - containerPort: 80   #内部服务暴露的端口
这里面定义nginx使用的镜像和创建多少个实例，以及container命名标记

当我们按照需要配置好deployment，使用kubectl apply 去创建部署(常见的几个 kubectl 命令可能需要记一下)

[root@master nginx]# kubectl apply -f nginx-deployment.yml 
deployment.apps/nginx-deployment created


创建Service
当我们创建部署完毕，nginx 服务仅仅只是部署，我们还需要让它暴露出自己的服务。
这就相当于给局域网里的电脑插上了网线，从此就可以对外公开自己的服务。

nginx-service.yml

apiVersion: v1
kind: Service  #该配置的类型，我们使用的是 Service 服务类型
metadata:
  name: nginx-service  #该服务类型的名称
spec:
  selector:    #选中的app部署实例
    app: nginx #为该Deployment设置key为app，value为nginx的标签
  ports:  #暴露的端口
  - protocol: TCP  # 走得tcp 协议
    port: 80 #默认端口
    targetPort: 80 #内建服务端口
    nodePort: 30080 #对外服务端口
  type: NodePort 
这里面呢，targetPort 就是对应着 deployment 的内网端口，nodePort 则是对外公开的端口。

[root@master nginx]# kubectl apply -f nginx-service.yml 
service/nginx-service created
打开浏览器，我们可以看到nginx服务已经对外开启



一个nignx服务 已经在集群跑起来了。
```

# K3s Server/Agent到底是干什么的？一共包含哪些部分？背后到底做了哪些事情？
```text
1. K3s Server 和 Agent 是什么及它们的作用
K3s Server
K3s Server 是 K3s 集群的控制平面，相当于集群的“大脑”，负责管理和协调整个集群的运行。它掌控着集群的全局状态，做出资源分配、调度等重要决策，确保集群中的应用程序按照用户的期望运行。

K3s Agent
K3s Agent 是运行在工作节点上的组件，它是集群的“四肢”。Agent 的主要任务是执行 Server 下达的指令，比如在节点上启动、停止和管理 Pod 等容器化应用。

2. 包含哪些部分
K3s Server
API 服务器（API Server）：作为集群的前端接口，提供 RESTful API 供用户、客户端工具（如 kubectl）以及其他组件进行交互。所有资源的创建、读取、更新和删除操作都要经过它。
控制器管理器（Controller Manager）：包含多个控制器，每个控制器负责特定的管理任务，比如确保 Pod 的副本数量符合预期、管理节点的生命周期等，不断将集群的实际状态调整到期望状态。
调度器（Scheduler）：根据节点的资源状况和 Pod 的资源需求，将新创建的 Pod 分配到合适的工作节点上运行。
嵌入式数据库：K3s 可以使用 SQLite 或 etcd 等嵌入式数据库来存储集群的状态信息，这些信息包括 Pod、节点、Service 等的配置和状态。
Cloud Controller Manager（可选）：如果 K3s 集群部署在云环境中，该组件可以将 K3s 与云服务提供商的 API 集成，实现负载均衡器、存储卷等云资源的管理。
K3s Agent
Kubelet：负责管理节点上的 Pod 和容器。它会接收来自 Server 的指令，启动、停止和监控 Pod 中的容器，确保容器按照预期运行。
Kube - proxy：在节点上实现网络代理功能，为 Service 提供集群内部的网络访问，负责将客户端的请求转发到对应的 Pod 上。
容器运行时：如 containerd，负责实际运行容器。Kubelet 通过与容器运行时交互来启动和管理容器。
3. 背后做了哪些事情
K3s Server
接收和处理请求：API 服务器接收来自各方的请求，对请求进行验证和授权，然后根据请求类型对集群资源进行相应的操作，如创建新的 Pod 或删除旧的 Service。
状态监测与调整：控制器管理器持续监测集群的状态，对比实际状态和期望状态。当发现不一致时，采取措施进行调整，比如增加或减少 Pod 的副本数量。
Pod 调度：调度器监听新 Pod 的创建事件，根据节点的资源使用情况和调度策略，选择最合适的节点来运行 Pod。
数据存储与管理：嵌入式数据库存储集群的所有状态信息，API 服务器在处理请求时会从数据库中读取和写入数据，保证数据的一致性和持久性。
K3s Agent
执行指令：Kubelet 接收来自 Server 的指令，根据指令在节点上创建、修改或删除 Pod 和容器。
容器管理：Kubelet 监控容器的运行状态，收集容器的资源使用信息，并将这些信息反馈给 Server。
网络代理：Kube - proxy 在节点上配置网络规则，将客户端对 Service 的请求转发到对应的 Pod 上，实现集群内部的网络通信。
4. 使用场景
K3s Server
边缘计算：在资源有限的边缘环境中，K3s Server 轻量级的特性使其能够快速部署和运行，管理边缘设备上的应用程序。
开发和测试环境：开发人员可以在本地或小型服务器上快速搭建 K3s 集群，使用 K3s Server 进行应用的开发、调试和测试。
小型企业和初创公司：这些企业可能没有足够的资源来部署和管理大规模的 Kubernetes 集群，K3s Server 可以在有限的资源下提供类似的功能。
K3s Agent
工作负载运行：在各种规模的集群中，K3s Agent 运行在工作节点上，负责实际运行用户的应用程序。
资源扩展：当集群需要扩展时，可以添加更多带有 K3s Agent 的节点，以增加集群的处理能力。
5. 底层原理
K3s Server
RESTful API 架构：API 服务器基于 RESTful 架构，通过 HTTP 协议提供服务。客户端和组件使用标准的 HTTP 方法与 API 服务器交互，这种架构便于不同系统的集成和扩展。
控制器模式：控制器管理器采用控制器模式，每个控制器都是一个独立的循环，不断监测和调整集群状态，确保集群的稳定性和可靠性。
调度算法：调度器使用多种调度算法，如基于资源利用率、亲和性和反亲和性等规则，来选择最合适的节点运行 Pod。
数据库持久化：嵌入式数据库使用持久化存储技术，将集群状态信息存储在磁盘上，保证在服务器重启或故障时数据不会丢失。
K3s Agent
Kubelet 交互：Kubelet 通过与 API 服务器通信，接收指令并执行相应的操作。它使用容器运行时接口（CRI）与容器运行时（如 containerd）交互，实现容器的管理。
网络规则配置：Kube - proxy 通过操作节点上的网络规则（如 iptables 或 IPVS），实现 Service 的网络代理功能，确保客户端能够正确访问到对应的 Pod。
综上所述，K3s Server 和 Agent 相互协作，构成了 K3s 集群的核心组件。Server 负责集群的管理和决策，Agent 负责在节点上执行具体的任务，它们共同为用户提供了一个轻量级、高效的容器编排和管理平台。
```
